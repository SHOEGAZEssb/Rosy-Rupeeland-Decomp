# Freshly-Picked Tingle's Rosy Rupeeland decompilation

This repository is an early matching-decompilation project for the European
Nintendo DS release of *Freshly-Picked Tingle's Rosy Rupeeland*.

## End goal

The long-term goal is a native, cross-platform build of the game, not merely a
rebuilt Nintendo DS ROM. Windows is the first target, but platform-independent
game code and portable interfaces should keep Linux, macOS, and other suitable
platforms viable. The matching NDS build remains the behavioral reference while
portable platform implementations replace Nintendo DS hardware and NitroSDK
dependencies.

Every newly understood subsystem should document the SDK boundary it crosses:
which NitroSDK or hardware service it calls, what behavior the game relies on,
and what portable implementation the Windows build will require. See
[docs/native_port.md](docs/native_port.md) for the porting strategy and SDK
barrier register.

The repository does not contain the game ROM, extracted game assets, Nintendo
SDK files, BIOS images, or proprietary compiler binaries. Supply your own ROM
and keep those materials outside version control.

## Tools

- `dsd` 0.11.0
- Ghidra 11.2.1 with `dsd-ghidra` 0.6.0
- objdiff 3.7.3
- Ninja 1.13 or newer
- Python 3
- MWCCARM 3.0 build 114
- MWLDARM 2.0 build 82

The proprietary compiler, linker, SDK, ROM, and license-manager files are
local prerequisites and must remain outside this repository. The local tools
are currently installed in `E:\Stuff\Decomp`; their paths are written only to
the ignored `build/config.ninja` file.

## Bootstrap

From PowerShell in the repository root:

```powershell
$env:DSD_EXE = 'E:\Stuff\Decomp\dsd.exe'
.\tools\bootstrap.ps1
```

The script verifies the input ROM hash, extracts it into `build/rom`, rebuilds
it, restores the retail secure-area checksum field, verifies an exact SHA-256
match as `build/tingle.original.nds`, and creates reference delink objects under
`build/decomp`. This output contains only the original binary code.

## Matching build

Configure the local Metrowerks, dsd, and objdiff paths, then build the current
matching unit:

```powershell
$env:MWCCARM_ROOT = 'E:\Stuff\Decomp\mwccarm\2.0\base'
$env:DSD_EXE = 'E:\Stuff\Decomp\dsd.exe'
$env:OBJDIFF_EXE = 'E:\Stuff\Decomp\objdiff-cli.exe'
.\tools\configure.ps1
ninja match
```

On the current machine the configuration script also detects those locations
without environment variables. `ninja match` performs all of the following:

- compiles the MT19937 and debug-menu source units with MWCCARM and assembles
  the matching input fallback with MWASMARM;
- archives all reconstructed objects with MWLDARM, exercising both
  proprietary tools;
- regenerates the relocation-aware target object with dsd;
- extracts and SHA-256 verifies the four functions from the ARM9 binary; and
- runs objdiff for all source units and enforces their exact sub-gates.

The MT19937 unit and complete debug-menu unit match all owned code and data at
`100.000000%`. The input unit keeps readable reconstructed C for all three
functions; the one compiler-resistant function has an exact matching assembly
fallback. Open `objdiff.json` from the repository root to use the GUI; its
custom build command is `ninja match`.

The complete debug menu is reconstructed: its constructor, destructor
variants, update, factory, and vtable are byte-exact. See
[docs/debug_menu.md](docs/debug_menu.md) for its behavior and addresses.

## Source-backed ROM

The first complete source-backed ROM is available with one command:

```powershell
ninja rom
```

Ninja builds the MT19937, input, and debug-menu replacements, substitutes them
for their original delink objects, links the ARM9, ITCM, DTCM, and all 647
overlays with MWLDARM, verifies every linked module with dsd, and repacks the
NDS. The output is `build/tingle.recompiled.nds`. All three replacements are
byte-exact after linking, so the ROM has the retail SHA-256.

See [docs/build.md](docs/build.md) for flags, artifacts, address ranges, and the
incremental link structure.

## Ghidra

Import the original ROM with the `dsd-ghidra` loader. When prompted, do not run
Ghidra's normal auto-analysis. Open the Script Manager and run `SyncDsd.java`
against `config/arm9/config.yaml`; that imports the module boundaries, symbols,
and relocations generated by `dsd`.

See [docs/status.md](docs/status.md) for current findings and known analyzer
exceptions, and [docs/startup.md](docs/startup.md) for the current ARM9 startup
and main-loop map. The first game-owned data structures and reconstructed C
functions are described in [docs/system.md](docs/system.md).
