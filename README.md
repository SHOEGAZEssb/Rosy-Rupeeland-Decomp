# Freshly-Picked Tingle's Rosy Rupeeland decompilation

This repository is an early matching-decompilation project for the European
Nintendo DS release of *Freshly-Picked Tingle's Rosy Rupeeland*.

## End goal

The long-term goal is a native, cross-platform source recompilation of the game,
not merely a rebuilt Nintendo DS ROM or a separately implemented clone. Windows
is the first target, but platform-independent recovered game code and portable
interfaces should keep Linux, macOS, and other suitable platforms viable. The
matching NDS build remains the behavioral reference while platform adapters
replace Nintendo DS hardware and NitroSDK dependencies.

Every newly understood subsystem should document the SDK boundary it crosses:
which NitroSDK or hardware service it calls, what behavior the game relies on,
and what portable implementation the Windows build will require. See
[docs/native_port.md](docs/native_port.md) for the recompilation strategy and SDK
barrier register.

The repository does not contain the game ROM, extracted game assets, Nintendo
SDK files, BIOS images, or proprietary compiler binaries. Supply your own ROM
and keep those materials outside version control.

## Tools

- `dsd` 0.11.0
- Ghidra 11.2.1 with `dsd-ghidra` 0.6.0
- objdiff 3.7.3
- Ninja 1.13 or newer
- Python 3
- MWCCARM 3.0 build 114
- MWLDARM 2.0 build 82

The proprietary compiler, linker, SDK, ROM, and license-manager files are
local prerequisites and must remain outside this repository. Resolved tool
paths are written only to the ignored `build/config.ninja` file.

## Bootstrap

From PowerShell in the repository root:

```powershell
$env:DSD_EXE = 'E:\Stuff\Decomp\dsd.exe'
.\tools\bootstrap.ps1
```

The script verifies the input ROM hash, extracts it into `build/rom`, rebuilds
it, restores the retail secure-area checksum field, verifies an exact SHA-256
match as `build/tingle.original.nds`, and creates reference delink objects under
`build/decomp`. This output contains only the original binary code.

## Matching build

Configure the local Metrowerks, dsd, and objdiff paths, then run the matching
build:

```powershell
$env:MWCCARM_ROOT = 'E:\Stuff\Decomp\mwccarm\2.0\base'
$env:DSD_EXE = 'E:\Stuff\Decomp\dsd.exe'
$env:OBJDIFF_EXE = 'E:\Stuff\Decomp\objdiff-cli.exe'
.\tools\configure.ps1
ninja match
```

The configuration script also detects its supported conventional local paths
without environment variables. `ninja match` performs all of the following:

- compiles reconstructed source and matching assembly fallbacks;
- archives all reconstructed objects with MWLDARM, exercising both
  proprietary tools;
- regenerates the relocation-aware target object with dsd;
- verifies configured reference slices; and
- runs objdiff and enforces every configured exactness gate.

Some compiler-resistant functions retain readable C alongside matching
assembly fallbacks. Open `objdiff.json` from the repository root to inspect
object differences; its custom build command is `ninja match`.

## Source-backed ROM

Build and verify the source-backed ROM with one command:

```powershell
ninja rom
```

Ninja substitutes configured source objects for their original delink objects,
links the ARM9, ITCM, DTCM, and all 647 overlays with MWLDARM, verifies every
linked module with dsd, and repacks the NDS. The output is
`build/tingle.recompiled.nds`; the build fails unless it has the retail
SHA-256. See
[docs/game_work.md](docs/game_work.md) for the singleton layout and
[docs/game_flags.md](docs/game_flags.md) for its flag-storage API.

See [docs/build.md](docs/build.md) for flags, artifacts, and the incremental
link structure.

## Ghidra

Import the original ROM with the `dsd-ghidra` loader. When prompted, do not run
Ghidra's normal auto-analysis. Open the Script Manager and run `SyncDsd.java`
against `config/arm9/config.yaml`; that imports the module boundaries, symbols,
and relocations generated by `dsd`.

See [docs/status.md](docs/status.md) for the technical baseline and known
analyzer exceptions, and [docs/startup.md](docs/startup.md) for the ARM9 startup
and main-loop map. Input state and random-number behavior are described in
[docs/system.md](docs/system.md).
